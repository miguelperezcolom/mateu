# client-rules

Pins that field-level `@Disabled` and `@Hidden(expr)` become client-side rules on `ServerSideComponent.rules` — `Rule(filter:"true", action:SetDataValue, fieldName, fieldAttribute:disabled|hidden, expression, result:Continue)` — rather than server-side field exclusion, so conditional visibility runs in the browser with no round trip. This is the whole reactive-form contract: a renderer that does not receive these rules shows a permanently-visible field, which is a silent behavioural break no port test would catch on its own. The case also pins rule ORDER (Java emits all disabled rules before hidden ones; the ports interleave per field — declaring the disabled field first makes the three agree) and the exact enum spellings (`SetDataValue`, `disabled`/`hidden`, `Continue`) on the wire.
