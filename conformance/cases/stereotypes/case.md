# stereotypes

Pins the field-stereotype vocabulary on the wire: an explicit stereotype declaration (slider and stars on int fields, textarea on a string) and the ports' idiomatic Password marker must all land in FormField.stereotype as the exact strings "slider"/"stars"/"textarea"/"password", with the dataType still derived from the field type (integer/string). This is the contract every renderer switches on to pick the widget — a port that spells a stereotype differently (or lets a marker override the explicit one) renders a different control for the same declaration. The three resolvers (Java FieldTypeMapper.getStereotype, .NET StereotypeOf, Python stereotype_of) all give an explicit Stereotype first priority and map Password → "password", so the wire should be byte-identical after normalisation. Textarea is declared via the explicit stereotype in all three on purpose: the Multiline marker is NOT equivalent across ports (Java @Multiline only sets the multiline flag and keeps stereotype "regular"; .NET/Python Multiline flips the stereotype to "textarea"), so using it here would pin a divergence instead of the stereotype set.
